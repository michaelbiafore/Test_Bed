## Why

Phase 1 established `RISK_TIERS.md` as the single authored source of truth for which paths Claude may
touch, but nothing yet *enforces* it — the tiers are advisory markdown a model can talk its way past.
Phase 2 adds the **structural** layer of the PROD-promotion spine (items R3, R4, A1 of
`Plans/PLAN_ZZ_Upgrade_01.md`): a generator that turns the risk tiers into a config the model cannot
bypass, a pre-edit guard on sensitive paths, and merge-gating CI for golden tests. These are built now
so the mechanism is in place and reviewed; they only *bite* once the Phase 3 reference app supplies a
real test command and real folders — but the wiring must exist and be proven first.

## What Changes

- **Add `scripts/gen-settings.mjs`** — a Node (cross-platform, runs on the Windows host with no WSL)
  script that parses the "Path assignments" table in `RISK_TIERS.md` and emits the `permissions`
  (`allow`/`ask`/`deny`) block of `.claude/settings.json`. Mapping: Low/Medium → `allow`, High → `ask`,
  Off-limits → `deny`; Off-limits rows also emit command/read deny boundaries (e.g. `Bash(*prod*)`,
  `Read(**/prod_data/**)`). Built **test-first**.
- **Add `.claude/settings.json`** — a new *committed* project settings file, generated by the script
  (permissions block) plus a wired `PreToolUse` hook entry. Merges with the existing git-ignored
  `.claude/settings.local.json` (personal `enabledPlugins` + allow-list), which stays untouched.
- **Add `scripts/warn-if-audit-path.ps1`** — a PowerShell `PreToolUse` hook (the host is Windows 11 /
  PowerShell, **not** `.sh`) that stop-and-confirms on edits to `ask`-tier / audit paths. A `.sh`
  variant ships only as a documented WSL fallback.
- **Add `.github/workflows/golden-gate.yml`** — a PR-triggered job running golden + regression tests.
  The test command is a clearly-marked placeholder that Phase 3 points at the real runner. Committed
  valid YAML, **not yet a required check**.
- **Add `.github/workflows/golden-drift-check.yml`** — a weekly cron re-running golden + regression and
  opening a GitHub issue on failure. Same placeholder caveat.

Non-goals: no renaming of any Phase 1 artifact; no second source of risk data (`RISK_TIERS.md` stays
sole); no attempt to make the CI checks *required* or the app runnable — that is Phase 3/4.

## Capabilities

### New Capabilities
- `risk-tier-permission-sync`: Deterministically generate the `.claude/settings.json` `permissions`
  block from the `RISK_TIERS.md` path-assignment table, so risk data is authored in exactly one place
  and the enforced config is derived, never hand-edited.
- `audit-path-edit-guard`: A pre-edit hook that interrupts and requires human confirmation before an
  edit proceeds against an `ask`-tier / audit-sensitive path.
- `golden-regression-ci`: CI workflows that run golden + regression tests on every PR (merge-gating,
  once required) and on a weekly schedule (opening an issue on drift).

## Impact

- **New files:** `scripts/gen-settings.mjs`, `scripts/warn-if-audit-path.ps1` (+ optional `.sh`
  fallback), `.claude/settings.json`, `.github/workflows/golden-gate.yml`,
  `.github/workflows/golden-drift-check.yml`, and a test for the generator.
- **Reads (does not modify):** `RISK_TIERS.md` (the tiers table is the generator's only input).
- **Untouched:** `.claude/settings.local.json` — Claude Code merges it over the generated file.
- **Tooling:** introduces the repo's first `scripts/` dir and its first executable test; a test runner
  (Node's built-in `node:test`) is selected so no new dependency is required.
- **Deferred bite:** the workflows reference a placeholder test command and the generator's tier rows
  are still the placeholder examples until Phase 3; nothing enforces against real code until then.
